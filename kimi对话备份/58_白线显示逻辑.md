## 修改说明

### 问题

P激活后，白色虚线（`interLine`）的显示逻辑存在bug：

- `updateGeometry()` 中无条件设置了 `interLine.visible = showHex`，导致切换圆锥曲线后白色虚线总是显示
- 但拖动ABCabc产生交点时，`updateInterLine()` 应该根据实际交点数量动态控制显示，却没有生效

### 修复内容

**1. `updateGeometry()` 中的修改**将原来的无条件设置：

JavaScript 复制

```javascript
// 更新连接线和交点可见性
const showHex = hexVisible && !params.isDegenerate;
[lineAb, ...].forEach(l => { if(l) l.visible = showHex; });
[interAB, interBC, interCA].forEach(p => { if(p) p.visible = showHex; });
if (interLine) interLine.visible = showHex;  // ← 问题：无条件显示
[labelP1, ...].forEach(lbl => { if(lbl) lbl.visible = showHex; });
```

改为计算交点后调用 `updateInterLine()`：

JavaScript 复制

```javascript
// 更新连接线和交点
const showHex = hexVisible && !params.isDegenerate;
[lineAb, ...].forEach(l => { if(l) l.visible = showHex; });
if (showHex && hexPoints.length === 6) {
    // ... 计算交点 iAB, iBC, iCA ...
    // ... 设置 interAB.visible, interBC.visible, interCA.visible ...
    updateInterLine();  // ← 根据实际交点数量控制显示
} else {
    [interAB, interBC, interCA].forEach(p => { if(p) p.visible = false; });
    if (interLine) interLine.visible = false;
}
[labelP1, ...].forEach(lbl => { if(lbl) lbl.visible = showHex; });
```

**2. `applyHexVisibility()` 中的修改**在 `else` 分支中显式隐藏 `interLine`：

JavaScript 复制

```javascript
if (showHex && hexPoints.length === 6 && ...) {
    // ... 计算交点 ...
    updateInterLine();
} else {
    if (interLine) interLine.visible = false;  // ← 新增：P关闭时隐藏
}
```

### 修复后的行为

- **无交点（线平行）**：白色虚线隐藏
- **拖动产生交点**：立即调用 `updateInterLine()`，动态检测交点数量，≥2个交点时显示白色虚线
- **无需切换圆锥曲线**：拖动过程中实时更新，不再需要切换曲线类型触发 `buildScene()`

## 核心设计原理

**母线追踪法**确保：

- 每个点绑定到一条固定的圆锥母线（由方位角 `theta` 定义）
- 曲线类型变化时，点沿同一条母线滑动到新截面的交点
- 抛物线→双曲线时，所有点自然落在同一支（因为它们共享相同的母线半空间）
- 不会出现跨支跳跃或点丢失的情况

## 设计原理

每个六等分点现在绑定到一条固定的圆锥母线（由方位角 `theta` 定义）。母线从锥顶出发，方向为 `(cosθ·sinα, -cosα, sinθ·sinα)`。当曲线类型变化时，点沿同一条母线滑动到新截面的交点。这确保了：

- **抛物线→双曲线**：抛物线上的点都来自同一"半锥"的母线，转成双曲线后自然落在同一支上
- **不会跨支跳跃**：因为母线方位角连续变化，不会突然跳到对面母线
- **退化模式也适用**：母线与退化平面的交点就是退化双直线上的位置
